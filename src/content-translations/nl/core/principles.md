## Pureline-kern {#pureline-core}

Deze regels gelden voor alle ondersteunde talen, voor zover de taal ze op een natuurlijke manier toelaat.

| ID | Regel |
|---|---|
| PL-CORE-001 | De besturingsstroom moet zo lineair mogelijk zijn |
| PL-CORE-002 | Vermijd `else` |
| PL-CORE-003 | Geef de voorkeur aan guard clauses |
| PL-CORE-004 | Gebruik de duidelijkste vorm van besturingsstroom voor de taal; talen met accolades gebruiken expliciete blokken |
| PL-CORE-005 | Idiomatische, taaleigen verkortingen zijn toegestaan zolang ze direct leesbaar blijven |
| PL-CORE-006 | Functies moeten klein en gefocust zijn |
| PL-CORE-007 | Namen moeten betekenis dragen |
| PL-CORE-008 | Vermijd onnodige abstracties |
| PL-CORE-009 | Vermijd God Classes en God Modules |
| PL-CORE-010 | Geef de voorkeur aan onveranderlijke toestand |
| PL-CORE-011 | Geef de voorkeur aan moderne taalfuncties waar die de duidelijkheid vergroten |
| PL-CORE-012 | Vermijd onnodige verticale opmaak |
| PL-CORE-013 | Opmerkingen mogen onduidelijke code niet compenseren |
| PL-CORE-014 | Behandel ongeldige toestanden en fouttoestanden vroeg |
| PL-CORE-015 | Houd belangrijke neveneffecten zichtbaar |
| PL-CORE-016 | Resources moeten een duidelijke levenscyclus hebben |
| PL-CORE-017 | Geef de voorkeur aan API's van het framework zelf |
| PL-CORE-018 | Vermijd magische waarden |
| PL-CORE-019 | Maak afhankelijkheden expliciet |
| PL-CORE-020 | Optimaliseer hot paths bewust, niet per ongeluk |
| PL-CORE-021 | Houd packages en bronmappen klein genoeg om in één oogopslag te overzien |
| PL-CORE-022 | Samenhang boven omvang: geef de voorkeur aan één samenhangende verantwoordelijkheid boven willekeurige regellimieten voor klassen |
