# Principes fondamentaux

[Guide de style de code](../README.md) · [Données originales 1.7](../../../PURELINE_SPECIFICATION_1.7.md)

## Pureline Noyau

Ces règles s'appliquent à toutes les langues supportées lorsque la langue les autorise naturellement.

| ID |Règle|
|---|---|
| PL-CORE-001 |Le débit de contrôle doit être aussi linéaire que possible|
| PL-CORE-002 |Éviter `else`|
| PL-CORE-003 |Préférer les clauses de garde|
| PL-CORE-004 |Utiliser le formulaire de contrôle-flux le plus clair pour la langue; les langues à base de supports utilisent des blocs explicites|
| PL-CORE-005 |Un raccourci-langue native idiomatique est autorisé lorsqu'il reste immédiatement lisible|
| PL-CORE-006 |Les fonctions doivent être petites et ciblées.|
| PL-CORE-007 |Les noms doivent avoir un sens|
| PL-CORE-008 |Évitez les abstractions inutiles|
| PL-CORE-009 |Évitez les classes de Dieu et les modules de Dieu|
| PL-CORE-010 |Préférez l'état immutable|
| PL-CORE-011 |Préférez les fonctionnalités de langage moderne où elles améliorent la clarté|
| PL-CORE-012 |Éviter le formatage vertical inutile|
| PL-CORE-013 |Les commentaires ne doivent pas compenser le code imprécis|
| PL-CORE-014 |Gérer les états d'erreur et invalides tôt|
| PL-CORE-015 |Gardez visible les effets indésirables importants|
| PL-CORE-016 |Les ressources doivent avoir un cycle de vie clair|
| PL-CORE-017 |Préférez les API-cadres-natives|
| PL-CORE-018 |Éviter les valeurs magiques|
| PL-CORE-019 |Expliciter les dépendances|
| PL-CORE-020 |Optimiser les chemins chauds délibérément, non accidentellement|
| PL-CORE-021 |Gardez les paquets et les dossiers sources assez petits pour scanner en un coup d'oeil|
| PL-CORE-022 |Cohésion sur taille: préférer une responsabilité cohérente aux limites arbitraires des lignes de classe|
